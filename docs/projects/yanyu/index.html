YAN YU QING CHENG / C-END MOBILE CONCEPT

堰遇青城

智慧文旅 App UI 与交互设计

围绕游客的信息判断、现场服务与文化体验，组织都江堰旅游的移动端任务路径。C 端移动应用概念设计。

01 / PRODUCT DECISIONS

围绕旅行任务，而非功能清单。

设计命题：游客在行前了解、景区现场和文化体验之间切换，所需信息与操作不同。界面需要把“了解、判断、行动”组织成连贯路径。

围绕旅行任务，而非功能清单。：从用户任务到产品决策与证据
用户任务 / 问题产品决策 / 取舍对应方案 / 证据
行前需要知道去哪、看什么。首页组织景区与推荐内容，景点详情承接进一步判断；避免将所有服务一开始平铺给游客。首页、门票列表和景区详情稿，分别承担总览、列表与具体信息层级。
现场需要快速定位服务。将地图、附近信息、停车与排队等入口集中在服务模块，让情境性任务有明确去处。服务页以地图和附近服务组织内容；位置与排队均为概念信息，未接入实时数据。
了解景区后，如何进入预约？把信息浏览与日期、景点、游客资料输入分开，减少同页任务混杂。景区详情与预约表单分别展示内容判断和输入操作，没有实际订单或支付验证。
地域文化如何延伸旅行体验？以发现、非遗与文创形成补充路径，不让 AI／AR 概念入口成为完成导览任务的唯一方式。发现、文创、非遗与导游对话稿作为设计证据；AI、AR 仅为 UI 概念，未声明模型或技术实现。
验证与边界

以上说明现有概念方案的任务分工，需求优先级尚待验证。没有已提供的访谈、现场可用性测试、实时定位、订票或 AI 服务实现证据。

02 / TASK & INFORMATION MODEL

把旅行情境，映射为清晰入口。

行前了解

做出出游判断

从景区、路线与文化内容了解目的地，再进入具体信息。

景区现场

找到眼前的服务

地图、导览和附近服务围绕当前位置组织界面。

文化延伸

让体验继续

非遗内容、文创与分享为旅游主线提供可选延伸。

一条示例任务路径 / CONCEPTUAL USER PATH

  1. 01

    发现目的地

    从首页或列表找到感兴趣的景区内容。

  2. 02

    了解具体信息

    通过详情阅读景区介绍与导览入口。

  3. 03

    选择日期与景点

    在独立预约页中完成选择与资料输入。

  4. 04

    回到服务与个人信息

    服务页承接现场任务，我的组织预约等信息入口。

五个一级入口
  • 首页
  • 服务
  • 发现
  • 文创产品
  • 我的

03 / SCOPE & TRADE-OFFS

让主任务不依赖额外能力。

优先组织

浏览与服务的基本路径

先说明景区信息从哪里找到、现场服务在哪里、预约需要哪些输入，再讨论更多入口。

模块取舍

主线与延伸分层

以首页和服务承接旅行主线，用发现与文创容纳文化内容，避免把每类内容都放在同一层。

能力边界

界面表达与系统实现分开

停车、排队、预约、AI 导游与 AR 都需要数据或技术支撑；现有材料只证明相关界面已设计。

04 / DESIGN EVIDENCE

用服务、详情与表单解释任务分工。

地图、讲解、停车与排队入口集中组织，说明现场任务的承接位置。

先提供景区介绍与内容，独立呈现需要阅读和理解的信息。

日期、景点与游客信息形成输入任务；不代表真实订单已经完成。

05 / NEXT VALIDATION

把设计问题，转成可观察的任务。

以下是下一阶段的原型验证计划，暂未提供真实测试或服务对接结果。

现场入口是否足够直接？

以寻找附近服务或停车信息为任务，观察首页与服务之间的分工是否清楚。

待观察：入口选择、返回行为与任务完成。

预约信息是否容易理解？

核对景点、日期与游客资料的输入顺序，以及用户是否理解其所在任务阶段。

待补充：原型、错误状态与表单反馈方案。

延伸内容会否打断主线？

检查文化、文创与导游入口是否影响基础导览；主任务应在不使用 AI 的情况下仍可理解。

待补充：任务优先级、无定位与数据不可用场景。
