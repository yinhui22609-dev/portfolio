# 十月与堰遇：产品叙事与证据边界

本文件累计记录移动应用案例的产品叙事、紧凑布局和中文主视觉更新。涉及 `mobile-cases.tsx`、`mobile-cases.module.css`、十月新增框架素材及本说明。此分任务没有修改首页、项目路由、个人简介和原始素材。

## 页面重心

两案均为 C 端移动应用概念设计，不改称已上线产品，也不为其补写 AI 能力、用户调研或效果数据。

- 十月：母婴社区 App 产品与 UI 交互设计。以“状态—内容—任务”说明产品逻辑。
- 堰遇：智慧文旅 App UI 与交互设计。以“了解—判断—行动”说明旅行任务如何分配到界面模块。

每页顺序：封面与定位 → 产品问题／决策／证据框架表 → 状态或任务模型 → 范围与取舍 → 三张关键界面证据 → 下一步验证问题 → 可展开的完整原始设计。

界面不再作为默认阅读中的连续截图墙。十月保留原 22 份素材并加入新框架图，堰遇保留 17 份；中文主视觉组合之外，各案默认保留三张关键证据，其余分组放入四个原生 `details`，可通过鼠标、触摸和键盘展开。原图预览继续复用 `CaseImage`。

## 十月：推理与证据

| 产品问题 | 组织方式 | 可核验的材料 |
| --- | --- | --- |
| 进入后如何确认阶段 | 四种状态使用不同字段；不把状态误画成必须依次完成的线性旅程 | 经期、备孕、怀孕、育儿四份状态表单 |
| 阶段内容如何被找到 | 阶段首页变化，导航入口保持稳定 | 备孕、孕期与宝宝首页，经期记录页 |
| 浏览之外如何承接行为 | 交流与个人记录分开组织 | 问答／广场／话题、经期日历、成长记录 |
| 工具应有什么边界 | 分类与入口作为概念交付；健康内容与隐私需另行验证 | 食材、营养、产检和儿歌原稿 |

四状态模型与核心任务路径均以真实 HTML 呈现。首页与表单保留准确名称，经期记录图不冒充经期首页。

默认的三张证据为怀孕状态、孕期首页、成长记录。其余状态、内容、社区、工具、视觉和样机放入原始设计档案，没有重复同一张图片充当不同功能。

状态理解、核心入口可找到性、内容可信度和隐私规则属于待验证项，没有已开展访谈或完成可用性测试的主张。宝宝起名独立界面、独立字体与组件规范继续明确标注缺口。

## 堰遇：推理与证据

| 产品问题 | 组织方式 | 可核验的材料 |
| --- | --- | --- |
| 行前如何了解目的地 | 总览、列表、详情分层 | 首页、门票列表、景区详情 |
| 现场如何找服务 | 地图与附近服务集中到服务模块 | 服务原始 UI |
| 了解后如何预约 | 内容判断和表单输入分开 | 景区详情、日期／景点／游客信息表单 |
| 文化内容如何延伸旅行 | 发现、非遗、文创形成可选路径 | 发现／非遗／文创 UI；AI 导游仅为概念界面 |

HTML 任务模型区分行前、现场与文化延伸，并保留五个一级入口。默认三张证据为服务、景区详情与预约表单；其余模块、原架构、导游与文化、品牌规范放入原始设计档案。

实时定位、停车／排队数据、订单／支付、AI 导游和 AR 未获得实现证据，页面未将其写成已接入。后续验证关注服务入口、预约字段顺序、错误反馈、无定位和数据不可用场景。

## 工程与检查

沿用现有服务端内容组件与共享 `ProductFramework`，没有增加客户端状态或生产依赖。原生 `details` 处理展开交互；媒体仍由共享图片组件优化并支持放大。新增样式为 CSS Module，四档布局由主任务统一验收。类型检查结果以最终主任务为准。
